# 部署说明（Windows / Linux）

Atoms Demo 是零第三方依赖的 Node 应用：**不需要 `npm install`、没有构建步骤**，把代码放上去、`node server.js` 就能跑。下面按平台给出可直接照抄的步骤，配套文件都在 `deploy/` 目录。

---

## 0. 先定三件事

| 决策 | 选项 | 怎么选 |
| --- | --- | --- |
| 跑在哪 | Windows / Linux 宿主机、Docker、PaaS（Render 等） | 有服务器就用 systemd/Docker；只想快速给评审看链接就用 PaaS |
| 数据存哪 | `STORAGE=sqlite`（单文件） / `STORAGE=redis`（Upstash REST） | 磁盘持久 → SQLite；**磁盘临时的免费平台 → Redis** |
| 要不要公网 + 模型 Key | 配 Key（体验真实模型） / 不配（Mock 模式） | Key 是平台级共享的，公网裸奔等于把额度公开。见第 6 节 |

## 1. 通用准备

**运行环境**：Node.js **24 或以上**（用到内置的 `node:sqlite`）。用 `node -v` 确认。

**配置方式**（二选一，优先级：界面 > 环境变量）：

- 界面里配：左下角「模型设置」→ 选服务商预设 → 粘贴 Key → 测试连接 → 保存。**配置存在数据库里，重启和重新部署都不丢**，推荐这种方式。
- 环境变量：复制 `.env.example` 为 `.env` 再改。

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | 监听端口 | `8787` |
| `STORAGE` | `sqlite` / `redis` | `sqlite` |
| `LLM_BASE_URL` | OpenAI 兼容接口地址 | `https://api.openai.com/v1` |
| `LLM_API_KEY` | 不填则进 Mock 模式 | 空 |
| `LLM_MODEL` | 模型名 | `gpt-4o-mini` |
| `LLM_MAX_TOKENS` | 单次输出上限 | `8000` |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | `STORAGE=redis` 时必填 | 空 |

> `.env` 与 `data/` 都在 `.gitignore` 里，**不会被提交、不会进源码包**。部署时注意别把 `.env` 提交上去。

## 2. Windows 部署

### 2.1 快速试跑（前台）

```powershell
cd C:\atoms-demo
node --disable-warning=ExperimentalWarning server.js
# 浏览器打开 http://localhost:8787
```

### 2.2 注册为开机自启服务（推荐）

仓库里给了脚本 `deploy\windows-service.ps1`，基于系统自带的任务计划程序，**不需要安装任何第三方工具**。用**管理员** PowerShell：

```powershell
cd C:\atoms-demo
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action install
```

它会：注册开机启动任务 → 立即启动 → 自动做一次健康检查。进程崩溃后按 1 分钟间隔自动重启。

日常运维：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action status     # 状态 + 健康检查
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action start      # 启动
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action stop       # 停止
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action uninstall  # 卸载
```

如果代码不在脚本所在目录的上一级，加参数指定：`-ProjectPath "D:\srv\atoms-demo" -Port 8787 -TaskName AtomsDemo`。

### 2.3 备选：NSSM（能用 services.msc / 优雅停止）

```powershell
nssm install AtomsDemo "C:\Program Files\nodejs\node.exe" "--disable-warning=ExperimentalWarning server.js"
nssm set AtomsDemo AppDirectory "C:\atoms-demo"
nssm set AtomsDemo AppStdout "C:\atoms-demo\logs\service.log"
nssm set AtomsDemo AppStderr "C:\atoms-demo\logs\service.log"
nssm set AtomsDemo AppExit Default Restart
nssm start AtomsDemo
```

### 2.4 防火墙与对外访问

服务默认监听 `0.0.0.0`，所以局域网内可直接访问 `http://<本机IP>:8787`。放行端口：

```powershell
New-NetFirewallRule -DisplayName "Atoms Demo 8787" -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow
# 只在局域网使用的话，收窄到本网段更安全：
# -RemoteAddress 192.168.1.0/24
```

查看本机 IP：`ipconfig`。要上公网建议前面挂 Nginx + HTTPS（写法同 3.4 节，Windows 上可用 Nginx for Windows 或 Caddy）。

### 2.5 升级与回滚

```powershell
cd C:\atoms-demo
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action stop
git fetch --all --tags
git checkout v1.0.0        # 或 git pull 到最新
powershell -ExecutionPolicy Bypass -File .\deploy\windows-service.ps1 -Action start
```

`data/` 在代码目录里，升级代码不会动它；但如果用 `git clean -xdf` 会连同 `.env` 和 `data/` 一起删掉 —— **先备份**。

### 2.6 备份（Windows）

```powershell
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$dir = 'D:\backup\atoms-demo'
New-Item -ItemType Directory -Path $dir -Force | Out-Null
Copy-Item C:\atoms-demo\data\atoms.db "$dir\atoms-$stamp.db"
Get-ChildItem $dir -Filter 'atoms-*.db' | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-14) } | Remove-Item
```

存成 `backup.ps1`，再用任务计划程序每天跑一次即可。

## 3. Linux 部署

以 Debian / Ubuntu 为例（RHEL 系把 `apt` 换成 `dnf`，Node 安装见 NodeSource 的 rpm 方式）。

### 3.1 安装 Node 24

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs
node -v     # 应输出 v24.x 或更高
```

> 不要用发行版仓库里的 `nodejs`（Ubuntu 22.04 只有 12/18），也不要用 nvm —— systemd 的 `ExecStart` 需要绝对路径，nvm 的路径随用户切换会变，容易踩坑。

### 3.2 放代码与建专用用户

```bash
sudo useradd -r -s /usr/sbin/nologin -d /opt/atoms-demo atoms
sudo mkdir -p /opt/atoms-demo
sudo git clone <你的仓库地址> /opt/atoms-demo     # 或用上传的 zip 解压
cd /opt/atoms-demo
sudo mkdir -p data
sudo chown -R atoms:atoms /opt/atoms-demo

# 模型配置放应用目录之外（推荐）
sudo tee /etc/atoms-demo.env >/dev/null <<'EOF'
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-替换成你的key
EOF
sudo chown atoms:atoms /etc/atoms-demo.env
sudo chmod 600 /etc/atoms-demo.env
```

### 3.3 用 systemd 托管（推荐）

```bash
sudo cp deploy/atoms-demo.service /etc/systemd/system/
sudo nano /etc/systemd/system/atoms-demo.service   # 需要时取消 EnvironmentFile 那行的注释
sudo systemctl daemon-reload
sudo systemctl enable --now atoms-demo
sudo systemctl status atoms-demo --no-pager
curl -s localhost:8787/api/health
```

单元文件要点（`deploy/atoms-demo.service`）：`Restart=always` 保证崩溃自愈；`ProtectSystem=full` + `ReadWritePaths=/opt/atoms-demo/data` 让代码目录只读、只放行数据目录可写；日志统一进 journal。

```bash
journalctl -u atoms-demo -f            # 实时日志
journalctl -u atoms-demo --since "1 hour ago"
```

### 3.4 Nginx 反向代理 + HTTPS

```bash
sudo apt install -y nginx apache2-utils
sudo cp deploy/nginx.conf /etc/nginx/conf.d/atoms-demo.conf
sudo nano /etc/nginx/conf.d/atoms-demo.conf       # 改 server_name 为你的域名

# 可选：全站加一层访问密码
sudo htpasswd -c /etc/nginx/.htpasswd atoms
# 然后取消配置里 auth_basic 两行的注释

sudo nginx -t && sudo systemctl reload nginx

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d demo.example.com          # 自动配置 HTTPS 与跳转
```

**两个必须注意的点**：

1. `proxy_buffering off` 不能删。生成过程是 SSE 流式推送，开着缓冲会让界面"卡住不动"，直到整段生成完才一次性出现。用 Caddy 或其他反代时同理，Cloudflare 代理（橙云）也会缓冲 SSE，建议给该域名关掉代理或改用直连。
2. `proxy_set_header X-Forwarded-Proto $scheme` 不能删。登录 Cookie 会在识别到 https 时自动加 `Secure`，丢了这行 HTTPS 下的登录态会异常。

### 3.5 Docker / Docker Compose

```bash
# 单容器
docker build -t atoms-demo:1.0.0 .
docker run -d --name atoms-demo --restart unless-stopped \
  -p 8787:8080 -v "$PWD/data:/app/data" \
  atoms-demo:1.0.0

# 或 compose（含健康检查与数据卷）
docker compose -f deploy/docker-compose.yml up -d --build
```

### 3.6 升级与回滚

```bash
cd /opt/atoms-demo
sudo systemctl stop atoms-demo
sudo git fetch --all --tags
sudo git checkout v1.0.0
sudo chown -R atoms:atoms /opt/atoms-demo
sudo systemctl start atoms-demo
journalctl -u atoms-demo -n 30 --no-pager
```

### 3.7 备份

```bash
sudo mkdir -p /var/backups/atoms-demo
sudo chmod +x deploy/backup.sh
crontab -e
# 每天 3 点备份，保留 14 天
0 3 * * * /opt/atoms-demo/deploy/backup.sh >> /var/log/atoms-backup.log 2>&1
```

恢复：停服务 → 把备份解压覆盖 `data/atoms.db` → `chown atoms:atoms` → 启服务。

## 4. 数据存储怎么选

| 场景 | 选型 | 原因 |
| --- | --- | --- |
| 自有服务器 / 本地 | `STORAGE=sqlite` | 单文件零运维；备份就是复制 `data/atoms.db` |
| Docker 带数据卷 | `STORAGE=sqlite` | 把 `data/` 挂出来即可 |
| 免费 PaaS（磁盘临时） | `STORAGE=redis` + Upstash REST | 容器重建不丢数据；镜像里已预留 `render.yaml` |

切换存储**不会自动迁移历史数据**（两种驱动的表结构不同）。要迁移就在旧环境用 SQLite 导出、新环境重新导入，或者干脆在切换前把需要的项目导出成单文件 HTML。

## 5. 排障清单

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| `EADDRINUSE` | 端口被占 | `netstat -ano \| findstr :8787`（Win）/ `ss -lntp \| grep 8787`（Linux），换端口或停掉占用进程 |
| 浏览器打不开 | 防火墙 / 只听了 localhost | 确认服务日志里是 `http://localhost:8787` 且监听 `0.0.0.0`；放行防火墙 |
| 生成时界面"卡住"，最后一次性出现 | 反代开了缓冲 | 关掉 `proxy_buffering`（见 3.4） |
| 登录后刷新又回到登录页 | Cookie 没带上 | 检查 `X-Forwarded-Proto`、域名是否一致、是否用了 http 访问 https 站点 |
| 页面 401 | 未登录访问接口 | 正常行为；先登录再说 |
| 模型报「返回的是网页不是 API 响应」 | 接口地址填成了控制台网址 | 改成 API 地址，如 `https://api.deepseek.com/v1` |
| 生成产物被截断（缺 `</html>`） | 输出触达上限 | 调大 `LLM_MAX_TOKENS`，或换非推理模型（如 `deepseek-chat`） |
| 产物一片空白 / 什么都没生成 | 推理型模型把正文写进了思考 | 已自动兜底；仍异常就换 `deepseek-chat` |
| `data/` 写不进去 | 权限 | `sudo chown -R atoms:atoms /opt/atoms-demo`（Win 下 SYSTEM 运行时确认目录可写） |

自查命令：

```bash
curl -s localhost:8787/api/health        # {"ok":true,"storage":"sqlite","llm":"live",...}
node tools/diag-llm.mjs                  # 模型连接逐项诊断（不打印 Key）
node tools/test-mock.mjs                 # 生成器自检
node tools/smoke.mjs                     # 端到端自检
```

## 6. 公网部署的安全清单

这几条不是可选项，是公网部署前必须做的决定：

1. **模型 Key 是平台级共享的**。任何注册用户都能替换它、消耗它。要么在 Nginx 层加 Basic Auth / IP 白名单（3.4 节），要么公网环境不配 Key、让访客走 Mock 模式。
2. **注册是开放的**。任何能访问站点的人都能注册账号。演示环境建议配合访问密码，或把注册入口收起来。
3. **`/api/data` 没有限流**。生成出来的应用可以无限制写数据，长期暴露需要加配额。
4. **已发布的应用对所有人可见**。给评审用的演示项目不要在里放真实敏感数据。
5. **一定要开 HTTPS**。否则登录 Cookie 会以明文在链路上传输。
